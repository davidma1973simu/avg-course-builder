# 设计期检查清单（可调用）

> 用途：设计/评审「课程 → AVG」转换产物时逐条核对。按平台设计工作区与通用门禁组织。
> 与 PRD 的 Validation 门禁、AVG Project JSON Schema 配合使用。

---

## 零、核心设计假设（锁定 · 不可动摇）

> **没有「应用迁移桥」，学习与产品不成立。** 本假设为平台前提，所有设计必须遵循。

- [ ] **探索世界默认采用「远」（虚构类比）情景**（如星际探索、古堡谜案），作为心理安全的练习场，而非仿真真实工作现场（「近」）。
- [ ] **无论「近」或「远」，复盘（Reflection）之后都必须有「应用迁移桥」**：学员把在虚构/类比世界中沉淀的方法论 / 工具 / 流程，迁移应用到**自身真实工作场景与挑战**。
- [ ] 应用迁移桥产出物：**真实场景应用卡 / 迁移行动计划**（真实挑战 + 选用方法 + 有时限第一步），离线包必须内嵌此模板（由 VR-RE05 校验）。
- [ ] 「近」仅在客户有强合规 / 强真实诉求时可选，但**应用迁移桥不可省**。
- [ ] 理由：虚构距离降低 ego 威胁、提升试错意愿与抽象能力；桥补上「翻译」，把体验变能力。详见 `Core_Design_Assumption`（仓库 docs/）。

## 一、按设计阶段（Pipeline）的检查清单

### Challenge（挑战）
- [ ] 知识点是否被包装成"需要取证/推理才能解开"的情境，而非直接讲授？
- [ ] 是否有明确"矛盾点/谜题"，且难度适中（非一眼看穿、非无解）？
- [ ] 线索是否来自 Exploration 阶段（线索卡 → 可推理）？
- [ ] 是否给出"真相子弹"且数量有限（制造取舍/压力）？

### Exploration（探索）
- [ ] 是否有多视角/多组信息差（每组探索不同线索，汇合互补）？
- [ ] 角色（NPC）是否有记忆/动机/能动性三支柱，会因学员行为改变态度？
- [ ] 全局 flag 是否控制在 3–7 个？状态是否产生可见后果？
- [ ] 探索路径是否有"自然汇合点"（瓶颈），避免组合爆炸？

### Decision（抉择）—— 红线：必须是真实取舍
- [ ] 是否 ≥2 个合理且各有 Trade-off 的选项（两难，而非对错题）？
- [ ] 是否避免了"明显正确的考试题"？
- [ ] 抉择是否从戏剧时刻**自然涌现**，而非打断叙事？
- [ ] 是否避免了"假选择"（若选择无关紧要，要么删掉，要么改为表达型）？
- [ ] 抉择频率是否变化（有呼吸），非恒定决策密度？

### Consequence / Growth（后果与成长）
- [ ] 选择是否导致可见的能力/关系值变化？
- [ ] 计量是否"可见且有意义"，阈值是否开门（解锁场景/结局/能力）？
- [ ] 多个计量是否可能"相互咬合"制造张力（无法既要又要）？
- [ ] 是否允许"非最优"选择也产生独特内容（避免完美唯一解）？

### Ending（结局）—— 红线：平行价值结局
- [ ] 是否生成多个**平行**结局（如最佳履约/妥协/失控），而非单一"通关"？
- [ ] 是否规避"真结局问题"（一个真结局使其他路径无效）？
- [ ] 每个结局是否"配得上"通往它的路径、提供闭环？
- [ ] 不同结局是否对应不同的**能力雷达**（可量化复盘）？

### Reflection（复盘）—— 红线：结构化复盘 + 可带走产出 + 应用迁移桥
- [ ] 是否内置 AAR 四步（目标→事件→差异→行动）或等效结构？
- [ ] 是否保证"心理安全 / Ask-before-tell / 证据锚定 / 命名行为不命名人"？
- [ ] 是否以"具体、有时限的承诺"收尾？
- [ ] 是否对成功也复盘（不只失败）？
- [ ] 离线包是否内嵌**可带走的成果模板**（能力雷达图/行动计划/共识制度）？
- [ ] **【强制】应用迁移桥**：复盘后是否有「将所学应用到学员自身真实工作挑战」的环节（真实挑战+选用方法+有时限第一步）？缺此则学习与产品不成立（VR-RE05）。

## 二、线下产品包（离线包）完整性清单

- [ ] 剧本本（主线 + 分支逻辑清晰）
- [ ] 角色卡（每组/每人：目标、秘密、背景、工作内容）
- [ ] 线索卡 / 物证（与 Exploration 对应，可被推理使用）
- [ ] 道具 / 物料清单（实体信物、计时沙漏、投票贴…）
- [ ] **DM 手册**：控场流程、时间线、分支指引、追问话术、意外卡
- [ ] **复盘手册 / 知识卡片库**：复盘引导 + 理论点 + 抽取规则
- [ ] 计分 / 投票工具（抉择记录、小组对比）
- [ ] **产出物模板**（能力雷达图、行动计划、共识制度）
- [ ] 多人运行设计：1 讲师带 6 组的同步节点、汇合节点、信息互补机制

## 三、通用质量门禁（参考 PRD Validation）

- [ ] **抉择质量**：所有 Decision 节点均通过"两难 vs 假选择"审查
- [ ] **分支健康**：无组合爆炸；状态变量 ≤7 全局 flag；无死锁分支
- [ ] **学习深度**：存在"探索→决策→后果→复盘"完整闭环（非纯观看）
- [ ] **角色代入**：角色有清晰目标与秘密，能"履职"而非"听课"
- [ ] **复盘强度**：有结构化复盘 + 可带走产出（否则只是娱乐）
- [ ] **线下可运营**：离线包组件齐全，DM 手册可让非原作者带场
- [ ] **一致性**：同一课程的四模块（设计阶段/JSON/预览/离线包）表达一致

## 四、调用示例（给 AI Agent 的提示范式）

> 当设计某一阶段时，先读取本 Skill 对应 references，再结合课程内容与 PRD Schema 产出；
> 产出后用上述清单逐条 self-check，未过门禁则迭代。

- 设计 Decision → 读 `avg_mechanics_library.md` 的 B/C/D + 本清单"Decision 红线"
- 设计离线包 → 读 `jubensha_playbook.md` 第 2/4/6 节 + 本清单"线下产品包完整性"
- 需要佐证 → 读 `case_library.md` 取真实案例
- 终检 → 本清单"通用质量门禁"
