一、产品定位与边界

AVG Course Builder 是一个 DIY 设计平台：输入企业培训课程材料，输出一套可运行、可测试、可修改、可导出的 AVG 课程原型，并最终落地为线下产品包（实体教学材料 + 形式载体），由引导师在物理课堂运营。

维度定位（本产品）非目标（明确不做）
产品类型课程→AVG 的 DIY 设计 / 生产平台在线 AVG 游戏运营平台
最终产出物线下产品包（盒装/卡/手册，可印刷）实时多人在线运行后端
运营方引导师在物理课堂平台提供的在线学习系统 / LMS
数据采集设计期质量校验（Validators/试玩）学员在线行为数据采集 / 学习分析
核心用户乙方讲师 / 甲方 L&D（prosumer）采购在线培训系统的企业 IT
边界红线：V1（及可预见未来）不做实时多人 SaaS、不做在线数据采集、不做 LMS。全景图中的「Browser-based Multiplayer AVG Prototype」是设计期原型预览/试玩；「讲师控制台 / 多人课堂运行层」是离线包里的生成物（讲师控制面板、同步节点等），不是在线系统。

二、用户角色

  • 创作者（乙方讲师 / 甲方 TD）：导入课程、确认映射、编辑设计、预览试玩、导出离线包。无「在线学员」角色。
  • 协作设计师：在 AI 草稿上做 20% 创意与质控（未来）。
  • 平台管理员：模板、模型、审核、计费、未来市场。

四、12 阶段生成 Pipeline（设计功能）

第一版固定 12 个阶段，每阶段有输入、AI 任务、人工确认、输出。尤其不能让 AI 先写剧情。9 个限权 Agent 负责生成，Validator 负责质量门禁：

阶段Agent输入输出（设计产物）
01 Course Import—PPT/PDF/Word/讲师手册CoursePackage（结构化课程）
02 CapabilityCapability AgentCoursePackage能力清单 + 预期行为改变
03 BehaviorBehavior Agent能力可观察学习行为
04 ChallengeChallenge Agent行为真实情境挑战
05 WorldWorld Designer挑战游戏世界（支持探索）
06 Character/NPCCharacter Agent世界主角 + NPC（独立目标）
07 ExplorationExploration Agent世界/NPC探索路径 + 信息系统
08 DecisionDecision Agent探索决策 + 后果（≥2 合理选项/trade-off）
09 ConsequenceConsequence Agent决策行为后果（失败有意义）
10 GrowthGrowth Agent后果能力成长
11 EndingEnding Agent成长多结局
12 ReflectionReflection Agent全链路学习复盘点
+ 运行规则Runtime Designer全链路多人运行设计（时间线/控制面板/同步节点）

六、Agent 架构与 System Prompt 原则

  • 每个 Agent 限权：只产出自已阶段的结构化 JSON，不越界写剧情。
  • 上下文通过统一数据模型在阶段间传递，避免「AI 先写故事」。
  • 成本护栏：长上下文摘要 + 阶段级缓存。
  • Validator 在每阶段后校验，不达标打回重生成。

Agent System Prompt 模板原则（以 Decision Agent 为例）：

你负责「决策」阶段。
输入：exploration 阶段的探索路径与信息系统。
任务：为玩家设计决策点。
硬性约束：
  - 每个决策必须有 ≥2 个合理选项；
  - 选项必须有真实 trade-off（不存在明显正确的“标准答案”）；
  - 不同选择必须导致不同后果（consequence 阶段承接）；
  - 不得给出“最优攻略”直接破解游戏；
  - 玩家不能因“不知下一步做什么”而卡死。
仅输出 JSON，不解释。

七、四工作区（设计视角）+ 编辑器

  • 理解工作区：课程导入、结构化、人工校正。
  • 映射工作区：Learning Gameplay Map 可视化与编辑（左学习目标 / 右游戏机制）。
  • 生成工作区：12 阶段 Pipeline 运行、Validator 门禁、人工确认。
  • 导出工作区：节点编辑器加工 → 设计期预览/试玩 → 生成离线包全部组件 → 导出可印刷格式。
  • AVG 编辑器：节点画布（对话/分支/决策/结局）+ 节点属性编辑器（选项/条件/变量/卡面绑定）+ 实时预览。

八、设计期原型预览 / Playtest（非部署产品）

「一键生成浏览器可玩的 2D AVG」用于作者在导出前试玩验证设计是否成立（对话/决策/状态/结局渲染，桌面+移动）。Game Tester 自动试玩并 AI 分析问题，输出 Prototype Test Report。它是设计期验证工具，不是交付给学员的线上产品。

九、线下交付物生成与导出（⭐真正产出物）

系统自动生成并导出整套离线包，组件覆盖《设计全景图》清单：

组件说明
剧情/脚本对话、分支、多结局
信息卡 / NPC卡 / 决策卡 / 任务卡 / 状态变量表玩家手里的事实与工具
角色分轨5–6 组不同剧本与角色
讲师控制面板 / 玩家界面说明引导师如何控场、玩家如何参与
多人运行设计公共事件时间线、各组状态/探索记录、信息发放规则、NPC使用规则、全班同步节点、最终汇合节点
测试报告AVG Quality Check + Prototype Test Report（随包交付）
导出格式PDF 拼版 / Word / InDesign + 物料清单 + 印刷规格
这是产品的交付红线：必须能导出「一套可线下运营的完整产品包」。它替代了原先「线上多人运行」的红线——因为运营本就发生在物理课堂。

十、技术架构（无实时多人后端 / 无在线数据采集）

  • 前端：四工作区 + 节点编辑器 + 设计期预览（浏览器，桌面/移动）。
  • 后端：Pipeline 编排服务（调用 9 Agent）+ Validator 服务 + 统一数据模型存储。
  • 导出服务：离线包组件渲染 → 印刷/拼版格式（PDF/Word/InDesign）+ 物料清单。
  • 存储：CoursePackage / 阶段产物 / 模板与素材库。
  • 不做：WebSocket 实时同步、学员行为数据库、在线鉴权与 LMS 集成。

十一、Validation 质量门禁（设计期）

AVG Quality Check 至少检查（来自《设计全景图》）：

  • 有没有真正的探索？有没有真正的选择？
  • 选择是否产生不同后果？有没有信息不对称？
  • 玩家是否必须主动寻找信息？有没有失败？失败是否有意义？有没有重新尝试的价值？
  • NPC 是否具有独立目标？不同路径是否最终覆盖核心学习内容？
  • 五六个小组能否同时运行？一个讲师能否管理？
  • 是否存在某条最优攻略直接破解游戏？是否存在玩家不知道下一步做什么而被卡死？
  • Learning Validator：学习目标是否真的通过游戏行为实现。
  • Runtime Validator：一个讲师能否同时运行六组（设计可行性）。

十二、V1 Vertical Slice 与 Task Backlog

V1 以《新任管理者团队管理》为端到端样例：乙方讲师 DIY 把真实课程跑通「导入→映射→生成→编辑→预览→导出」，产出可印刷离线包，并验证速度（≤小时级）、质量（Validators 通过）、成本（订阅 vs ¥5K–50K 代理）。

完整开发任务见 Task Backlog v2：9 个 Epic / 22 用户故事，按 M1–M4（约 13 周）推进；开工顺序 E0→E1→E2→E3→E4→E5→E6→E7→E8；护城河/红线 = E2（LGM 学习玩法映射） 与 E6（离线包导出）。

十三、非功能需求与里程碑

  • 性能：单门课端到端生成 ≤ 小时级；编辑器实时保存。
  • 可复制：模板化，一门课一次生成、多班复用。
  • 成本护栏：Agent 调用有预算与缓存。
  • 合规：课程素材权属确认、内容审核。
  • 里程碑：M1 基座/解析/映射 → M2 生成/编辑器 → M3 预览/导出离线包（红线）→ M4 质量迭代/乙方 DIY 验收。
  • V1 不做：3D、复杂角色动画、语音 NPC、开放世界、复杂经济系统、复杂 AI NPC（来自《设计全景图》明确清单）。

11.2 校验执行与产物

执行闭环：加载 AVG Project JSON → 对每条 `auto=true` 规则按 JSON 路径求值 → 收集 BLOCKER/WARN/INFO → 输出 `kit.qualityReport`（AVG Quality Check + Prototype Test Report 合并），随离线包交付。导出离线包（E6）前必须 VR-OFF* 全过；发布前必须全部 BLOCKER 全过。

校验触发点：① 每阶段生成后（限权 Agent 产出即校验，不达标打回）；② 设计期预览/试玩后（Game Tester + AI 分析）；③ 导出离线包前（VR-OFF* 全过方可导出）。规则引用的扩展节点子 Schema 见 PRD 第 5 节注释与 `validation_rules.json`。

核心设计假设（锁定 · 不可动摇）

一句话：AVG 的探索世界默认采用「远」（虚构类比）情景，作为心理安全的练习场；学员在虚构中体验 / 试错、沉淀方法论与工具， 复盘后必须强制「应用迁移桥」——把所学迁移到学员自身真实工作场景。无论近 / 远，没有这条，学习与产品不成立。

  • 远（默认）：星际探索 / 古堡谜案等类比世界，用距离降低 ego 威胁、提升试错与抽象能力。
  • 近（可选）：仿真真实工作现场；仅在客户强合规 / 强真实诉求时选用，但应用迁移桥不可省。
  • 应用迁移桥（强制）：真实挑战 + 选用方法 + 有时限第一步 → 离线包内嵌「真实场景应用卡」。
  • 校验：新增 VR-RE05（BLOCKER），缺桥不得发布。详见 Core_Design_Assumption。

课程分层 3×2 矩阵（设计要求 · 设计前前置判定）

设计要求：任何课程进入平台，必须先完成【课程准入与分层判定】（Course Intake & Tiering）， 输出 tier / track 判定后，主流程（Pipeline）才启动。该判定是 Pipeline 的第 0 阶段前置输入，不是可选步骤。 完整矩阵与盲区见 Course_Tiered_Matrix。

  • Tier（3 层）：L1 轻量切片 3h / L2 标准单元 7h / L3 深度系列 14h；AVG 探索体验严格占总时长 50%（VR-TIER01 BLOCKER）。
  • Track（2 类）：C1 通用改编（已有课程转译）/ C2 定制业务赋能（先萃取再构建，必含能力模型与水平；VR-TIER03）。
  • 非 AVG 50%：导入 + 复盘结构化产出 + 工作场景应用 + 个人行为改变计划（IDP）四活动齐全（VR-TIER02 BLOCKER）；应用与 IDP 模板独立、均指向真实场景。
  • Pipeline 第 0 阶段（Intake & Tiering）：输入检查（完整 / 脱敏 / 版权）→ 分层判定（tier/track + 50/50 时间预算 + 定价/工时锚）→ 产出 Intake 卡片 → 才进入 Course → Capability → …（VR-INTAKE01 BLOCKER：无判定不得进入 Pipeline）。
  • 清单嵌入：Sample_Input_Checklist 第 11 项「分层与前置判定」由课程主人预先自评，Intake Agent 复核后写入 AVG Project JSON 的 kit.intake。
