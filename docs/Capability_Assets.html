AVG × 剧本杀 场景化学习设计能力资产

你是「课程 → AVG」场景化学习平台的设计顾问知识库。本 Skill 沉淀两大学科里被验证过的真东西， 供平台设计期（AI Agent 与课程设计师）随时调用，把"课程"变成"好玩且学得会的游戏化情景"。

两大知识支柱

  1. 游戏 / 桌面游戏里优秀 AVG 的互动与设计机制

视觉小说、互动小说、冒险游戏（如 *Zero Escape*、*Danganronpa*、*Ace Attorney*、

*Detroit: Become Human*、*Disco Elysium*、*Along the Edge*、*The Hundred Line*）。

学的是：分支与状态追踪、抉择质量、证据/辩论系统、关系/道德计量、多视角、实时压力、

时间循环、多结局、活体 NPC、元叙事——以及它们为什么有效。

  1. 现有剧本杀（沉浸式情景）用于企业培训「产品设计 → 实际交付运营」的方法论

相邻的真实产出物赛道（邮储《阳光之下》、农行《清风廉影》、兴业《大岭山之歌》、

工行《铁路大厂》、《星际启航》《列车藏宝》《职场局中局》等）。

学的是：线下产品包该有哪些组件、设计流程、现场交付节奏、引导（DM）技术、

复盘（Debrief）方法论、运营迭代——以及本平台如何用速度/质量/成本/规模化碾压它。

八条跨领域心法（调用前先读）

  1. 受控的能动性（Constrained Agency）：作者设计"可能性空间"，玩家在其中导航。

用虚构内的约束（人物性格、环境、信息差、时间压力）而非任意限制来收口。

  1. 抉择质量 > 抉择数量：宁要少数真正分叉的真抉择，不要大量假选择。

玩家一旦发现选择无关紧要，信任即崩塌。

  1. 复盘是灵魂：没有结构化复盘的体验只是娱乐。复盘把"经历"变成"学习"，

是平台 Reflection 阶段与离线包里"复盘手册/知识卡片"存在的根本原因。

  1. 真结局问题（True-Ending Problem）：多结局应是"不同价值的平行结果"，而非"真/假"排行；

否则玩家会为最优解优化，而非角色扮演。让每个结局都"配得上"通往它的路径。

  1. 状态最小集：只追踪真正产生可见后果的状态（剧情 flag / 关系值 / 资源 / 特质），

3–7 个全局 flag 足够；状态必须落到可见变化上。

  1. 线下包的"可带走产出物"：剧本杀学习迁移的关键，是学员带走的成果

（能力雷达图、行动计划、共识制度）。本平台离线包必须内嵌可带走的成果模板，

否则培训"热闹但业务不变"。

  1. 核心假设：远场景 + 应用迁移桥（不可动摇）：AVG 探索世界默认用虚构类比（远）情景制造心理安全，

学员在虚构中体验/试错、沉淀方法论与工具；复盘后必须强制「应用迁移桥」——把所学迁移到学员自身真实工作挑战。

没有这条，学习与产品不成立（校验 VR-RE05）。详见仓库 docs/Core_Design_Assumption。

  1. 产品分层 3×2 矩阵（定价 / 交付 / 生产轴）：课程产品按【复杂度/时长 3 层 × 定制化程度 2 类】结构化。
  • 3 层：L1 3h / L2 7h / L3 14h，AVG 探索固定占 50%，另 50% 为 导入 + 复盘结构化产出 + 工作场景应用 + 个人行为改变计划（IDP）。
  • 2 类：C1 通用改编（已有课程转译）/ C2 定制业务赋能（先萃取再构建学习目标/内容/场景/能力/评价）。

设计任一门课先定 Tier 与 Track——它决定 AI 生成深度、离线包规格与定价套餐。详见 docs/Course_Tiered_Matrix 与 references/course_tiering.md。

调用方式：根据当前任务，读取对应 references/ 文件，提取机制/方法论/清单， 结合 PRD 的 12 阶段流水线、AVG Project JSON Schema、Validation 门禁给出设计建议。

01 · AVG 互动与设计机制库

AVG 互动与设计机制库

来源：优秀视觉小说 / 互动小说 / 冒险游戏的设计实践。 目的：为「课程 → AVG」平台各设计阶段提供可借鉴的互动机制，并说明"为什么有效"。 每条机制都给出：是什么 / 代表游戏 / 为什么有效 / 映射到本平台哪一阶段 / 设计要点 / 反模式。

A. 分支与状态追踪（Branching & State-Tracking）

是什么：用变量（flag、关系值、资源、特质）记录玩家历史，在后续内容中触发"条件内容"， 而非为每个选择都另开一条平行剧情线。

代表：

  • *Zero Escape* 系列：内置流程图（Flowchart）作为"叙事建筑"——24 个结局，部分锁在"需先探索其他路线才能获得的信息"之后；流程图本身就是情感载体（迷宫感=被困感）。
  • 钻石模式（Diamond Pattern）/ 瓶颈结构（Bottleneck）：分叉后重新汇合到固定节点，避免组合爆炸。
  • 折叠回退（Foldback）：分支在关键节拍汇合，用状态 flag 制造"同结构、不同质感"。

为什么有效：在"无限选择幻觉"与"可控创作成本"间取得平衡；让每个玩家旅程都显得独特，又不至于内容指数膨胀。

映射到本平台：

  • Exploration（探索）：分支探索不同线索/区域
  • Decision（抉择）：选择改变状态而非另开世界线
  • Consequence / Growth（后果/成长）：状态积累改变后续场景与结局

设计要点：

  • 识别"自然汇合点"，用瓶颈收口；让汇合后的路径因之前行为而"定制感"十足（换几句台词/环境细节）。
  • 全局 flag 控制在 3–7 个；状态必须产生可见后果（Gate / Variation / Consequence）。

反模式：组合爆炸（每条选择都开新线）、状态混乱（变量泛滥、互相矛盾）。

B. 抉择设计（Choice / Dilemma Design）

是什么：把"决定"做成有意义的分叉。

类型说明质量
二元道德对 vs 错❌ 过于简单，避免
两难（Dilemma）两种"善"的冲突，理性人会分歧✅ 最佳
表达型结果相同，但展现角色特质✅ 若真实可信
策略型风险/回报权衡✅ 类游戏 IF
探索型选择探索哪条路径✅ 调节节奏

代表：*Along the Edge* 用"非善/恶二元"的选择，让选择贯穿始终、由内而外改变主角（外貌、衣裙、性格）。

为什么有效：当玩家"基于价值观而非最优解"做选择时，会真正代入角色、为结果负责。

映射到本平台：Decision 阶段的核心。平台的 Decision 必须是"真实取舍（≥2 个合理且各有 Trade-off 的选项）"，不是"明显正确的考试题"。

设计要点：

  • 避免明确的对与错；创造让理性人产生分歧的两难。
  • 抉择频率要变化（让故事在抉择点之间"呼吸"），不是恒定决策密度。
  • 假选择（表达型）可用，但要让玩家"通过选择定义角色"，而非"假装有影响"。

反模式：迷宫模式（选项是带正确/错误路径的导航谜题）、优化游戏（一个结局明显最优）。

C. 证据 / 辩论系统（Evidence / Argument System）

是什么：给玩家"物证 + 逻辑"工具，在特定环节用证据击穿谎言/矛盾，完成推演。

代表：

  • *Ace Attorney*：法庭交叉讯问。每个环节只有一个关键矛盾，把正确证据对上去；慢节奏、逐步逻辑。
  • *Danganronpa*：学级裁判（Class Trial）。Nonstop Debate（对话飞过，用"真相子弹"=证据射中弱点/谎言）、Hangman's Gambit（拼出关键词）、Bullet Time Battle（节奏对决）、Closing Argument（拼漫画还原犯罪过程）；有"影响值/HP"随错误下降；可把一句陈述当"闪回子弹"去击穿另一句。

为什么有效：把"被动看剧情"变成"主动用证据推理"；错误有代价、正确有即时正反馈；多人辩论氛围强化临场感。

映射到本平台：

  • Challenge（挑战）：把知识点包装成"需要取证/推理才能解开"的情境
  • Decision（抉择）：把"选哪个方案"升级为"用证据支撑你的判断"
  • 多人课堂：小组辩论 + 投票，对应 Nonstop Debate 的"群体讨论找出黑幕"

设计要点：

  • 证据来自 Exploration 的线索搜集（线索卡 → 证据库）。
  • 给"矛盾点"高亮、给"真相子弹"有限数量（制造取舍与压力）。
  • 错误要有代价但可重试；最后用"Closing Argument"式环节让学员复述/还原逻辑链。

反模式：证据与论点脱节；"唯一矛盾"太明显缺乏挑战。

D. 关系 / 道德计量（Relationship / Morality Meters）

是什么：用数值追踪玩家与角色的关系、或自身的道德/立场倾向，并据此开门/改结局。

代表：*Detroit: Become Human*

  • Connor 的 Software Instability（异常度）与 Hank 信任值 是相互咬合的系统：共情选择抬高异常度，也会赢得 Hank 信任；冷酷机器路线则反之。两个值共同决定 Connor 能否在 Crossroads 成为"异常者"。
  • Public Opinion（公众舆论）像主角的血条，决定最终结局分支。

为什么有效：把抽象"你是个什么样的人"变成可感知、会累积、影响结局的变量；让"小选择"也有重量。

映射到本平台：

  • Consequence（后果）：选择权导致能力/关系值变化
  • Growth（成长）：值达到阈值解锁新场景/新结局/新能力
  • 多人课堂：每组有"团队信任/任务进度"计量，对应 Hank 信任这类关系值

设计要点：

  • 计量要"可见且有意义"，阈值开门（如 trust ≥ 70 解锁秘密任务）。
  • 多个计量可相互咬合（制造"无法既要又要"的张力）。
  • 让"非最优"选择也能产生独特内容（避免完美通关唯一最优）。

反模式：计量与剧情脱节（纯打分）、计量过多导致维护灾难。

E. 多视角 / 角色切换（Perspective Switching）

是什么：同一事件用不同角色视角讲述，玩家的认知随视角拼合而深化。

代表：

  • *Far Away*：9 条主线、16 个结局、300+ 抉择，靠"视角 + 累积线索"而非恋爱分支支撑犯罪谜题。
  • *Detroit*：三条主角线交替推进，最终在 Crossroads 汇合；玩家同时是三个人的"导演"。

为什么有效：让世界显得"真实存在、持续运转"；不同视角制造信息差与戏剧张力；天然适合分组（每组 = 一个视角/阵营）。

映射到本平台：

  • Exploration（探索）：多组各自探索不同线索/区域，信息互补
  • 多人课堂：6 组 = 6 个视角/阵营，汇合时拼出全貌（对应 Detroit 三线汇合）
  • Role（角色分配）：每组扮演不同利益相关方

设计要点：

  • 视角差异要制造"信息差"而非重复剧情。
  • 汇合点（如 Detroit 的 Crossroads）是高潮——各组带着不同情报碰撞。

反模式：视角只是"换皮说同一件事"。

F. 实时压力与 QTE（Real-time Pressure / QTE）

是什么：在时间限制/操作压力下做决定，提升临场感。

代表：*Detroit* 的 QTE（查案、逃亡、按 R2 记忆宫殿）、高手模式缩短反应窗口；*Danganronpa* 辩论有计时。

为什么有效：压力让"选择"有重量、记忆深刻；模拟真实职场"必须在时限内决断"。

映射到本平台：

  • Challenge（挑战）：限时决策/限时取证
  • 线下包：用"计时沙漏/倒计时卡"在实体场景制造压力

设计要点：压力要服务剧情，不是为难；失败可重试，但要有"后果感"。

反模式：压力与学习无关、纯操作炫技（*Danganronpa* 的 Bullet Time Battle 被评"与剧情脱节"）。

G. 时间循环（Time Loop）

是什么：事件重复，玩家保留记忆，后续选择基于之前尝试；结局常固定但"理解"加深。

代表：*Outer Wilds*、*Twelve Minutes*；*Zero Escape* 用"需先走其他路线才能解锁信息"近似时间循环的信息结构。

为什么有效：把"失败"重新定义为"收集信息的必要轮次"；鼓励实验与反思。

映射到本平台：

  • Reflection（复盘）："重玩理解"——复盘就是职场的时间循环，用新认知重看当时决策
  • 用例：安全/合规类课程，让学员"回到事故前"用新认知重决策

设计要点：循环要有"记忆延续"的明确反馈（"你这次知道 X 了"）。

H. 多结局与"真结局问题"（Multiple Endings）

是什么：根据累积状态通向不同结局。

代表：

  • *Along the Edge*：60+ 结局，选择贯穿始终改变主角命运与配角生死。
  • *The Hundred Line*：100 endings，用流程图驱动"what-if"探索；有真结局但不削弱其他。

真结局问题：若一个结局是" canonical 真结局"，其他结局会被玩家视为"失败/无效"，于是玩家为最优解优化而非角色扮演——破坏代入。

为什么有效（正确做法）：让每个结局都"配得上"通往它的路径；结局是"不同价值的平行结果"，而非排行。

映射到本平台：Ending 阶段。平台要生成多个平行结局（如"最佳履约/妥协/失控"），对应不同能力雷达，而非单一"通关"。

设计要点：

  • 所有结局都应是"有效结果"，不要惩罚式"坏结局"。
  • 结局给"闭环"与"值得体验"，不是失败状态。

反模式：一个真结局使其他路径无效化；坏结局只是惩罚。

I. 活体 NPC（Living NPCs: Memory / Motive / Agency）

是什么：NPC 记住玩家行为、有自己的诉求、并按自身逻辑行动——而非复读机。

代表：Questas 的"Living NPCs"三支柱：

  • Memory：全局 flag（救了 Mara？） + 关系值（mara_trust 0–100）
  • Motive：NPC 想要什么、愿用什么交换
  • Agency：NPC 如何跨分支按动机行动

为什么有效：把"选 A 还是 B"变成"你支持了谁、背叛了谁、赢得了谁的信任"——玩家记住的是关系，不是路线。

映射到本平台：

  • Exploration（探索）：NPC（剧中角色/客户/下属）有记忆与动机，会因学员行为改变态度
  • 多人课堂：引导师（DM）扮演关键 NPC，按组的选择即兴反应

设计要点：3–7 个全局 flag；关系值门控特殊场景/结局；NPC 在不同分支"带着更新后的目标"重现。

J. 元叙事 / 破墙（Meta）

是什么：游戏"知道自己是被玩的"，用破墙制造反思。

映射到本平台：Reflection 阶段可用"元提示"——"你刚才的选择，在真实工作中会怎样？"把剧情与职场直接打通。

K. 流动图表作为情感载体（Flowchart as Emotional Register）

代表：*Zero Escape* 流程图随探索"生长"，既导航又传递"被困迷宫"的情绪；若做成整齐树状则失去张力。

映射到本平台：设计期预览的"流程图/路线地图"不仅要能跳节点，其形状本身应能传递剧情主题（如分支网状=错综利益）。

02 · 剧本杀企业培训方法论

剧本杀企业培训：设计 → 交付 → 运营方法论

来源：国内真实"课程→剧本杀/沉浸式情景"企业培训赛道（相邻竞品、真实产出物）。 目的：本平台最终产出物是与竞品一样的线下产品包，因此必须吃透"剧本杀是怎么设计、交付、运营的"。 关键认知：剧本杀培训 ≠ 娱乐剧本杀。它的灵魂是复盘（Debrief），没有结构化复盘的剧本杀只是团建。

1. 为什么参考剧本杀（相邻真实赛道）

  • 国内没有"课程→AVG"软件平台，但有"课程→剧本杀"的产出物赛道，抢同一块培训预算、同一类学习目标（角色扮演 + 复盘）。
  • 真实案例：邮储《阳光之下》廉洁剧本杀、农行《清风廉影》、兴业银行《大岭山之歌》红色剧本杀、工行《铁路大厂》党建剧本杀、《星际启航》（新员工职业素养）、《列车藏宝》（问题分析与解决）、《职场局中局》（管理者技能）、《冰川之下》（目标计划）、《陆拾公园迷案》（服务营销）。
  • 它的痛点 = 我们的机会：单门课生产 1–3 个月、定制 ¥5K–50K/套 + 现场 DM、无数据回流、难多人分组同屏。本平台把"单门课 AVG 化"压到小时级 / 订阅摊薄。

3. 设计流程（选题 → 上线）

  1. 根据课程主题定剧本杀主题
  2. 根据课程目的确定剧本类型（推理/情感/经营/红色…）
  3. 根据授课人群确定角色（角色要让人"找到定位"）
  4. 根据授课内容设定故事大纲
  5. 根据角色工作设定角色故事
  6. 根据培训目的/预期设计结局与评分（阶梯式评分：不同选项赋予不同成长值；干扰项设计为"看似合理但非最优"）
  7. 剧本创作 → 道具设计 → 体验流程设计 → 测试与上线

设计理念范例（吴婷）："先成剧中人，再悟剧中意" + "演、练、学、化"四步教学法。

4. 现场交付流程（典型 1 天 / 6 小时，或五幕结构）

开幕剧 + 剧情介绍
  → 阅读剧本（读本）
    → 角色自我介绍（建立角色认同）
      → 第一轮线索搜查
        → 第一轮讨论
          → 第一轮投票
            → 第二轮线索搜查与讨论
              → 第二轮投票
                → 真相揭示
                  → 【复盘】（灵魂环节）
  • 线上版常做"一幕深度体验"；线下规划"五幕主线 + 2–3 幕替补剧目"，按企业性质/学员情况灵活抽选（应对关键学员缺席或强化某主题）。
  • 角色认同技巧：让学员用剧中名字互相称呼——"当学员用剧中名字称呼彼此时，角色认同自然产生，他们不是来听课，是来履职"。

5. 引导技术（Facilitation / DM 技术）

  • 教练式提问（"为什么？"）：学员分享决策后，不表面认可，而是深挖背后的思考过程。"问题问得很深，尤其回答后追问，建立了与课程的信任感。"把管理者从"完成任务"拉向"反思过程"。
  • 知识卡片动态匹配：理论点（如 4D 领导力、六顶思考帽）做成"知识卡片库"，根据学员现场表现抽取最相关的 10–20 张讲解，而非一刀切灌输。呈现方式要"活动化"（提问、朗读、讨论），不打断沉浸。
  • 戏剧冲突 / 意外卡：制造 PK、落选者不"出局"而由 CEO 协调安排其他职位；"意外卡"——如讨论陷入瓶颈时 CEO 突然敲门介入，模拟真实变数。
  • AI 作为思考伙伴而非替代：学员起初把"助攻卡"直接丢给 AI 生成"形式上正确但无落地"的内容——转化为教学契机：先 AI 生成草案，再小组讨论修订，产出"可带回工作的具体方案"。
  • 三师节奏：多位引导师扮演不同节奏的引导者（快慢交替），控制戏剧张力。

6. 复盘方法论（灵魂 —— 对应平台 Reflection）

没有结构化复盘的体验只是娱乐。复盘把"经历"变成"学习"。

四步法 / After-Action Review（AAR，美军、行动学习通用）

步问什么要点
1 回顾目标我们想达成什么？回溯初衷，对照实际结果
2 盘点事件关键亮点/不足是什么？实事求是，不夸大不回避
3 分析原因为什么？成功因做对什么？失败因什么？审慎质疑"揽功诿过"；主客观都质疑
4 总结规律/行动学到了什么？下次怎么不同？规律要经质疑；落到具体、有时限的承诺

通用复盘四问（flux.am / AAR）：

  1. What did we expect?（预期）
  2. What happened?（事实）
  3. Why the difference?（差异原因）
  4. What will we sustain/improve?（持续或改进）

复盘设计原则（务必遵守）

  • 心理安全：明确"无评判区"，人人都用了当时最优信息做决定。
  • Ask before tell：先放大参与者自己的洞察，再给理论；学习才粘得住。
  • 证据锚定：用抉择记录、能力变化、行为标签等"证据物"避免空泛。
  • 命名行为，不命名人：谈"这种行为在真实工作中会怎样"，不评判人。
  • 以承诺收尾：每次复盘结束要有"具体、有时限的下一步行动"；无承诺的复盘=无改变。
  • 对成功也要复盘：只复盘失败=只学避损；复盘成功=可复制的洞察。
  • 时长参考：工作坊中复盘≈场景时长；微场景更短， cohorts 可加深。
平台映射：Reflection 阶段 = 把 AAR 四步结构化成离线包里的"复盘手册"； Facilitator Console 导出"各组抉择轨迹 + 能力雷达"作为复盘证据物。

7. 运营与迭代

  • 试讲 → 学员共迭代：试课阶段邀请学员参与优化选题、互动、奖励规则（某管理沙盘课：1 期试讲 + 2 期落地，满意度 98.4%）。

Challenge（挑战）

  • [ ] 知识点是否被包装成"需要取证/推理才能解开"的情境，而非直接讲授？
  • [ ] 是否有明确"矛盾点/谜题"，且难度适中（非一眼看穿、非无解）？
  • [ ] 线索是否来自 Exploration 阶段（线索卡 → 可推理）？
  • [ ] 是否给出"真相子弹"且数量有限（制造取舍/压力）？

Exploration（探索）

  • [ ] 是否有多视角/多组信息差（每组探索不同线索，汇合互补）？
  • [ ] 角色（NPC）是否有记忆/动机/能动性三支柱，会因学员行为改变态度？
  • [ ] 全局 flag 是否控制在 3–7 个？状态是否产生可见后果？
  • [ ] 探索路径是否有"自然汇合点"（瓶颈），避免组合爆炸？

Decision（抉择）—— 红线：必须是真实取舍

  • [ ] 是否 ≥2 个合理且各有 Trade-off 的选项（两难，而非对错题）？
  • [ ] 是否避免了"明显正确的考试题"？
  • [ ] 抉择是否从戏剧时刻自然涌现，而非打断叙事？
  • [ ] 是否避免了"假选择"（若选择无关紧要，要么删掉，要么改为表达型）？
  • [ ] 抉择频率是否变化（有呼吸），非恒定决策密度？

Consequence / Growth（后果与成长）

  • [ ] 选择是否导致可见的能力/关系值变化？
  • [ ] 计量是否"可见且有意义"，阈值是否开门（解锁场景/结局/能力）？
  • [ ] 多个计量是否可能"相互咬合"制造张力（无法既要又要）？
  • [ ] 是否允许"非最优"选择也产生独特内容（避免完美唯一解）？

Ending（结局）—— 红线：平行价值结局

  • [ ] 是否生成多个平行结局（如最佳履约/妥协/失控），而非单一"通关"？
  • [ ] 是否规避"真结局问题"（一个真结局使其他路径无效）？
  • [ ] 每个结局是否"配得上"通往它的路径、提供闭环？
  • [ ] 不同结局是否对应不同的能力雷达（可量化复盘）？

Reflection（复盘）—— 红线：结构化复盘 + 可带走产出 + 应用迁移桥

  • [ ] 是否内置 AAR 四步（目标→事件→差异→行动）或等效结构？
  • [ ] 是否保证"心理安全 / Ask-before-tell / 证据锚定 / 命名行为不命名人"？
  • [ ] 是否以"具体、有时限的承诺"收尾？
  • [ ] 是否对成功也复盘（不只失败）？
  • [ ] 离线包是否内嵌可带走的成果模板（能力雷达图/行动计划/共识制度）？
  • [ ] 【强制】应用迁移桥：复盘后是否有「将所学应用到学员自身真实工作挑战」的环节（真实挑战+选用方法+有时限第一步）？缺此则学习与产品不成立（VR-RE05）。

二、线下产品包（离线包）完整性清单

  • [ ] 剧本本（主线 + 分支逻辑清晰）
  • [ ] 角色卡（每组/每人：目标、秘密、背景、工作内容）
  • [ ] 线索卡 / 物证（与 Exploration 对应，可被推理使用）
  • [ ] 道具 / 物料清单（实体信物、计时沙漏、投票贴…）
  • [ ] DM 手册：控场流程、时间线、分支指引、追问话术、意外卡
  • [ ] 复盘手册 / 知识卡片库：复盘引导 + 理论点 + 抽取规则
  • [ ] 计分 / 投票工具（抉择记录、小组对比）
  • [ ] 产出物模板（能力雷达图、行动计划、共识制度）
  • [ ] 多人运行设计：1 讲师带 6 组的同步节点、汇合节点、信息互补机制

三、通用质量门禁（参考 PRD Validation）

  • [ ] 抉择质量：所有 Decision 节点均通过"两难 vs 假选择"审查
  • [ ] 分支健康：无组合爆炸；状态变量 ≤7 全局 flag；无死锁分支
  • [ ] 学习深度：存在"探索→决策→后果→复盘"完整闭环（非纯观看）
  • [ ] 角色代入：角色有清晰目标与秘密，能"履职"而非"听课"
  • [ ] 复盘强度：有结构化复盘 + 可带走产出（否则只是娱乐）
  • [ ] 线下可运营：离线包组件齐全，DM 手册可让非原作者带场
  • [ ] 一致性：同一课程的四模块（设计阶段/JSON/预览/离线包）表达一致

三、校验执行说明（给 Validator Agent）

  1. 加载：读取当前 AVG Project JSON（统一数据模型）。
  2. 求值：对每条 auto==true 的规则，按 path 取字段、按 check 判定；auto==false 的规则输出人工复核项。
  3. 分级：收集 BLOCKER 失败 → 阻断 meta.status 进入 published，返回定位（ruleId + JSON path）给生成 Agent 重生成；WARN → 进 Quality Report；INFO → 人工确认清单。
  4. 产物：输出 kit.qualityReport（AVG Quality Check + Prototype Test Report 合并），随离线包交付。
  5. 门禁闭环：导出离线包（E6）前必须 VR-OFF* 全过；发布前必须全部 BLOCKER 全过。
调用方式：开发某阶段时读本文件对应行，或让 Validator Agent 直接加载 validation_rules.json。

  • 覆膜：光膜（亮） / 哑膜（质感、防指纹）。封面、控制面板常用哑膜。
  • 局部 UV：在指定图案上涂 UV 光油，突出 logo / 关键卡面。
  • 烫金 / 烫银：金属箔热压，用于标题、角色名，提升质感。
  • 激凸（击凸）：压出浮雕触感，常用于盒面 logo。
  • 模切：异形裁切，用于物证袋口、特殊卡形。
  • 圆角：卡牌四角打磨，防卷边、手感好。
  • 装订：骑马钉（薄册）/ 胶装（厚册）/ 圈装·活页（DM 手册，可摊平书写）/ 蝴蝶装（高档）。
  • 专色 / 压纹：品牌色精确还原 / 纸面纹理。

三、通用规范（导出服务必须遵守）

  • 出血：四周各 3mm；裁切边外不留任何内容。
  • 安全边：关键文字 / 图案距裁切边 ≥ 8mm。
  • 字号：正文 ≥ 9pt；小字（卡面备注）≥ 7pt；避免极小字在印刷后不可读。
  • 字体：中文建议 思源黑体 / 思源宋体 / 方正系列（注意商用授权）；嵌入字体或转曲。
  • 色彩：使用 CMYK；屏幕 RGB 色需转 CMYK 并核对，避免荧光色印不出。
  • 二维码 / 条码：四周留白 ≥ 4mm 安静区。
  • 拼版：导出 PDF 按 印刷拼版（imposition） 或提供单页 + 出血，方便印厂拼版。

07 · 课程产品分层模型（3×2）

课程产品分层模型（3×2 矩阵）

何时调用：当用户要定义「这门课该做成哪一档产品」「定价套餐」「AI 生成深度」「离线包规格」， 或设计某门课程的 Tier（L1/L2/L3）与 Track（C1/C2）时调用。完整文档见仓库 docs/Course_Tiered_Matrix.*。

一、两个维度

维度一 · 3 层（Tier）—— 按内容/场景复杂度与系统程度，对应总学习时长

  • L1 轻量切片：3h，AVG 1.5h，单模块 / 单一能力点，单角色单决策链 2–3 结局。
  • L2 标准单元：7h，AVG 3.5h，完整主题 / 2–3 能力点，2–3 角色多结局轻状态。
  • L3 深度系列：14h，AVG 7h，多模块 / 系统能力，多视角深度分支状态系统多轮复盘。

维度二 · 2 类（Track）—— 按定制化程度

  • C1 通用改编（Existing-to-AVG）：输入=已有成熟课程（PPT+教材），流程=转译现有 LGM，交付=标准盒装包，定价=订阅/按门改编。
  • C2 定制业务赋能（Bespoke Enablement）：输入=业务目标+真实案例，流程=先萃取（主题建模→关键事件访谈→能力建模→场景挑战→评价设计），交付=定制包（萃取报告+能力模型+定制场景库+评价量表），定价=项目制。

三、50 / 50 时间分配（核心约束，VR-TIER01/02 强制）

AVG 探索体验固定占总时长 50%；另 50% 为非 AVG 工作坊，由四项构成，且每门课都必须齐全： ① 导入（情境铺垫/目标共识）② 复盘结构化产出（AAR+可带走产出物）③ 工作场景应用（当堂迁移真实任务）④ 个人行为改变计划 IDP（30–60 天契约）。

四活动在 50% 内的分层权重（设计建议）：

  • L1：导入 40 / 复盘 35 / 应用 15 / IDP 10
  • L2：导入 25 / 复盘 30 / 应用 25 / IDP 20
  • L3：导入 15 / 复盘 25 / 应用 35 / IDP 25
③ 与 ④ 不可混：应用=当堂套真实业务任务（团队层）；IDP=个人 30–60 天行为契约（个人层）。两者模板独立，且都指向真实场景（满足 VR-RE05）。

四、盲区要点（设计时必须主动覆盖）

  1. 评价体系分层：L1 决策自评+知识；L2 能力雷达+行为承诺；L3 行为改变追踪+业务指标。
  2. C2 独有的【萃取】前置阶段——决定它从「业务目标」而非「现成 PPT」起步。
  3. 能力模型与水平（Novice→Proficient）：C2 必定义，驱动场景难度与雷达刻度；C1 复用原课程框架。
  4. 多人课堂运行强度随层递增；L3 需「多线并行+汇合」设计，离线包含同步/汇合节点物料。
  5. 迁移桥真实场景来源：C1 用行业通用案例，C2 用客户真实业务场景（VR-RE05 都强制）。
  6. 数据回流（虽线下）：复盘产出物（雷达/IDP）带回做课程迭代，是 C2 护城河。
  7. 质量门禁分层：L1 放宽叙事深度；L3 强制全量；C2 强制萃取+能力模型校验。
